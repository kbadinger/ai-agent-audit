### [2026-06-08] Sprint 12 — Threat-Landscape Currency Refresh
Assessment ~4 weeks after the last work (Sprint 11.5, 2026-05-12). Tool was healthy
but threat intel had gone stale. Web research surfaced major post-May-12 events for
both supported agents that the tool was blind to, and Kevin chose to wire a *real*
feed (not extend the synthetic corpus). Key decisions:

- **Real IOC feed = abuse.ch ThreatFox.** Chosen for its no-auth JSON export
  (`/export/json/recent/`), which drops straight into the existing `ioc_updater`.
  `update_from_url`/`--file` now auto-detect ThreatFox vs the native schema, so the
  feed mechanism is reusable. Live fetch validated: ~4,185 indicators at the time.
- **New CVEs are version-gated, not config-faked.** OpenClaw "Claw Chain"
  (44112/44113/44115/44118, all fixed 2026.4.22) and Hermes core CVEs (9368, 10548)
  are code-bug CVEs with no user-config toggle. Detecting them via an
  `agent_version_check` sweep is the honest mechanism; inventing config keys would
  have been fabricated data. Hermes' mixed version schemes (date `2026.4.x` vs webui
  semver) are handled by only comparing date-scheme installs to date-scheme CVEs.
- **Hermes finally has real detection content.** The profile existed since Sprint 11
  but carried zero Hermes intel; the Sprint 11 review explicitly deferred per-profile
  content until "Hermes-specific intel emerges." It has now (CSA's "9 CVEs in 4 days",
  Repello threat model), so `hermes_hardening` covers the genuinely-detectable
  defaults (HERMES_WRITE_SAFE_ROOT, container approval bypass, --yolo, skill
  setup.commands), and the Hermes `skills_path` was corrected to `~/.hermes/skills`.
- **Latent bug found + fixed:** `MemoryPoisoningMonitor.name` ("memory_poisoning")
  never matched the enrichment table key ("memory_poisoning_monitor"), so real
  memory-poisoning findings had always shipped un-enriched. Root-caused and renamed.

Result: 27 sweeps (was 25), 233 tests (was 198), v0.3.0, plus the project's first
CI workflow.

### [2026-07-19] v0.4.0 — Current-Schema Correctness Refresh
The July review found that the main risk was no longer missing detection ideas;
it was false assurance caused by product drift. OpenClaw now accepts JSON5 and
uses current paths such as `gateway.auth.mode`,
`agents.defaults.sandbox.mode`, `logging.redactSensitive`, and embedded
`mcp.servers`. Hermes uses `~/.hermes/config.yaml` and keeps its main memory
root at `~/.hermes/`, not a cloned OpenClaw workspace/schema.

The chosen boundary is to parse each product through `agent_config.py`, ingest
the installed product's structured native audit, and normalize both into the
existing Finding model. Independent process/network/file/session monitoring,
IOC matching, correlation, reporting, and exports remain this project's
value-add. Config remediation no longer writes copied schema keys; OpenClaw's
native fixer runs only after a backup and the backup is restored if the command
fails or leaves an invalid config. Hermes config remains manual until Hermes
publishes a supported native fixer.

Scan completeness is now first-class. Modules report `ok`, `degraded`,
`skipped`, or `error`; denied process/network visibility is `UNKNOWN` and earns
no security-score credit. Only complete successful sweeps resolve prior
findings, while degraded/error sweeps preserve evidence. Periodic sweep
findings now use the same alert path as monitor findings.

Threat intelligence also became lifecycle-aware: generic CVE/GHSA records are
bundled and refreshed from GitHub repository advisories, and ThreatFox data is
treated as a replaceable source snapshot with provenance and `last_seen`
confidence aging. This supersedes the original three-dependency goal by adding
`json5` and `PyYAML`; accurate parsing of supported agent formats was judged
more important than preserving the smaller dependency count.


## AI Analysis

_Generated by SubFrame onboarding on 2026-03-27_

**Vision:** Comprehensive security audit daemon that monitors OpenClaw AI agent installations for vulnerabilities, malicious activity, and misconfigurations — covering the OWASP Agentic Top 10 threat landscape.

**Tech Stack:**
- Python 3.10+
- SQLite (stdlib sqlite3)
- Jinja2 (HTML report templating)
- watchdog (filesystem monitoring)
- psutil (process/network monitoring)
- argparse (CLI)
- threading (concurrent monitors)
- Unix double-fork (daemon mode)

**Key Decisions:**
- **Minimal dependency footprint** (2026-03-01, superseded 2026-07-19): Originally only watchdog, psutil, and jinja2. json5 and PyYAML were added when current product formats made strict stdlib JSON parsing incorrect. The project still uses stdlib urllib and sqlite3.
- **Plugin architecture via abstract base classes** (2026-03-15): BaseMonitor and BaseSweep ABCs allow adding new security checks without modifying the engine. Monitors are callback-based (threaded, always-on), sweeps are run-and-return (periodic).
- **Centralized enrichment pipeline** (2026-03-20): All findings pass through mappings.enrich() and PrecisionTracker.calibrate() before storage, ensuring consistent MITRE ATT&CK/OWASP ASI tagging, remediation guidance, and confidence scoring across all detection modules.
- **Environment profiling to skip irrelevant checks** (2026-03-22): EnvironmentProfiler detects what's installed (Docker, MCP, skills, gateway) so sweeps like docker_security or mcp_security are skipped when their targets don't exist, reducing noise and scan time.
- **Confidence calibration from triage feedback** (2026-03-27): PrecisionTracker learns from human triage (confirmed/false_positive) to adjust future confidence scores per detection rule, with a minimum sample threshold before adjustments kick in. Low-confidence findings are still stored but suppressed from alerts.
